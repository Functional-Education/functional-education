Recursive thinking with functional blocks

Learn the basics of recursive functions without mutable data by assembling the key pieces of a correct solution.

Goal

Understand how a recursive algorithm stops and how it reduces the problem at each step.

Key idea

A recursive function has a base case and a recursive case. The base case stops the process, and the recursive case calls itself on a smaller input.

Functional style

No mutation. We create a new result from the current value and the recursive result.

Step 1

Mini theory

In the exercises, you are not just putting blocks in the right order. You are building the shape of a recursive function. A correct answer needs the right idea and the right indentation.

1

Start with the base case. For the sum function, when n == 0, the answer is 0. In the exercise, that means the return 0 block belongs inside the if n == 0: block.

2

Then add the recursive case. The function keeps working on a smaller input, here n - 1. In the exercise, the recursive return block stays at the same level as the if, not inside it.

3

Make sure it terminates. Every recursive call must move the input closer to the base case. If it moves away (for example n + 1), the function never stops.

Example with sum

This is the structure for the sum function that sums the first n natural numbers.

function sum(n):
    if n == 0:
        return 0
    return n + sum(n - 1)

So in practice: add the if block, drop return 0 onto it to indent it, then place the recursive return block below at the main function level.

Step 2

With or without mutation?

Both functions below compute the same sum. Only one of them follows the idioms of functional programming. Compare how each one gets to the answer.

Iterative, with mutation

function sum(n):
    total = 0
    i = 1
    while i <= n:
        total = total + i
        i = i + 1
    return total

The variables total and i are changed at every step of the loop. To know what the function returns, you have to follow how their values change over time.

Recursive, without mutation

function sum(n):
    if n == 0:
        return 0
    return n + sum(n - 1)

No variable is ever changed. Each call gets its own value of n, and the result is built by combining n with the value returned by the smaller call.

Takeaway: in the exercises, blocks such as n = n - 1 change a variable. A functional solution never needs them: pass the smaller value directly to the recursive call instead.

Step 3

Reading a recursion tree

A recursion tree shows every call a recursive function makes. The first call is at the top. Each call it makes appears one level below it. Reading it downwards shows how the input gets smaller until the base case. Reading it upwards shows how the returned values are combined into the final answer.

A function that terminates

sum(3) → 3 + 3 = 6
└── sum(2) → 2 + 1 = 3
    └── sum(1) → 1 + 0 = 1
        └── sum(0) → 0   (base case)

The input goes 3, 2, 1, 0, so it reaches the base case. Then the values go back up: 0, then 1 + 0, then 2 + 1, and finally 3 + 3 = 6.

A function that never stops

sum(3) → ?
└── sum(4) → ?
    └── sum(5) → ?
        └── sum(6) → ?
            └── … never reaches a base case ✗

Here the recursive call is sum(n + 1). The input grows instead of shrinking, so n == 0 is never true and no call ever returns.

When a function calls itself more than once, like Fibonacci, each call has several children and the tree branches. In the activity, an AI-generated recursion tree of your own solution appears every time you check your answer, with a short comment on what happens in it.

Reflection

        

          Look back at the four functions you built. Think about each question before you open
          the answer.
        


        

          What do all the base cases have in common?
          

            Each one handles the smallest input, where the answer is known without any further
            call: n == 0, n <= 1, the empty string, or a word of
            length 0 or 1. It is the only place where the recursion stops.
          

        


        

          How does each recursive call make progress?
          

            The input always gets strictly smaller: n - 1, n - 2,
            rest(text), middle(word). Because it shrinks at every
            call, it is guaranteed to reach the base case.
          

        


        

          Where did the correct solutions use mutation?
          

            Nowhere. No variable is ever reassigned. Each result is built by combining the
            current value with what the smaller call returns, using + or
            and.
          

        


        

          What did the recursion trees show you?
          

            Going down the tree, the input gets smaller until a leaf, which is always a base
            case. Going up, each call combines the results of its children. A tree that never
            reaches a leaf means the calls are not making progress towards the base case.
